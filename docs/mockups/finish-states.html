Spindle finish states

One frame per lifecycle state of docs/run-lifecycle.md, plus a closed-done run that is not a clean success, an abandoned end the table does not name, and unknown. Each frame draws the band above the prompt and the run pane with spindle-design's crab and band code. Only closed-done's celebration moves: six crew crabs hop once within 3 seconds, and nothing moves under reduced motion. Every value is invented for the mock-up.

Live states

running

The run works: round 1 of review, three reviewers at work.

running · MSP selected

The same run with limiter-core selected: its live reviewers under Working, its finished workers under Done.

shipped

Every MSP's pull request is open; lighthouse runs over the FEATURE branch during Integration.

reopened

A shipped run takes round 3 before its FEATURE pull request merges; it reads shipped again once it ships.

Final states

closed-done

A clean success: the thread closed done, no MSP shipped as a draft and lighthouse is green. The crew hops once, then the band settles to one line.

closed-done-plain

closed-done without a green lighthouse verdict: a plain Done that says why there is no celebration.

closed-draft

The run ended with a draft pull request for the blocked MSP; its bar and stage rail stop short of done.

stopped-critical

A hard failure stopped the run at review with nothing pushed.

superseded

The run was abandoned unfinished because rate-limit-api-2 replaced it.

cleaned

Clean-up deleted the run home after writing the run record; the thread has not closed yet.

abandoned

An abandoned end the lifecycle table does not name, shown with the run.end reason.

unknown

The event log could not be read, so spindle cannot say how the run ended.
